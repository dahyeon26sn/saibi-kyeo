## 문제 정의

- 팀 자체 설문(51명): 76%가 낯선 사람의 접근이나 원치 않는 종교 권유를 겪었고, 64%가 상대의 의도를 알아차리기 어렵다고 답했습니다.
- 가장 어려운 점: ① 자연스럽게 벗어나기 ② 의도 알아차리기 ③ 관련 정보·장소를 미리 확인하기
- 서울과기대신문 조사(162명)에서도 83%가 포교를 겪거나 목격했고, 92.6%가 대처법을 전혀 모른다고 답했습니다.

## AI 포교 의심도 판별 — 어떻게 개선했나

### 기존 방식(v1)의 문제
단어가 들어 있는지만 보고 점수를 매겼습니다.
- "복**도**" → '복'(칭찬·운세)으로 인식, "**다음** 주 설명회" → 재만남으로 인식
- "연락처는 **안** 물어봤어요" → 연락처 요구로 인식 (부정문 미처리)
- "근처 센터로 가자", "얼버무렸어요"처럼 단어 목록에 없는 표현은 놓침

### 개선 방식(v2) — `js/judge.js`
1. **표현 패턴**: 단어 대신 "연락처 + 요구 동사", "장소 + 이동 표현"처럼 표현 단위로 찾기
2. **부정문 처리**: 같은 절 안에 '안·않·없' 등이 있으면 해당 신호 제외
3. **안심 신호**: 학생회·공식 설문, 등록 동아리, 아는 사람, 거절하자 바로 물러남 → 점수 감소
4. **위험 조합 규칙**: 연락처+재만남, 장소 이동+다른 신호, 비밀 요구+다른 신호 → '상'
5. **확인 질문(체크리스트)**: 연락처 요구, 장소 이동·재만남, 소속 회피, 거절 후 붙잡음
6. **AI와 결합**: Claude 환경에서는 등급 정의와 예시를 넣은 프롬프트로 AI 판단을 받고, 규칙 엔진 결과와 크게 엇갈리면 중간 등급으로 조정

### 평가 결과

| 데이터 | 사례 수 | v1 정확도 | v2 정확도 | '상'을 '하'로 놓친 수 |
|---|---|---|---|---|
| 개발용 사례 (`data/cases.json`) | 47 | 55% | 96% | 4 → 0 |
| 팀 테스트 사례 (새로 작성) | (작성 예정) | | | |

> 개발용 사례는 엔진을 조정할 때 함께 본 사례라 실제 성능보다 높게 나옵니다. 공정한 성능은 엔진을 만들 때 보지 않은 **팀 테스트 사례**로 `eval.html`에서 측정합니다.

## 실행 방법

빌드 과정이 없는 정적 웹페이지입니다.

- **GitHub Pages**: 저장소 → Settings → Pages → Branch를 `main` / `root`로 저장하면 1~2분 뒤 주소가 생깁니다.
- **내 컴퓨터**: VS Code의 Live Server 확장으로 `index.html`을 엽니다. (파일을 더블클릭해 열면 위치 기능과 `eval.html`의 사례 불러오기가 동작하지 않습니다.)
- 관리자 화면(데모): 주소 뒤에 `?admin=1`을 붙여 엽니다.

## 파일 구조

```
index.html        앱 전체 화면
js/judge.js       포교 의심도 판별 엔진 (v1 비교용 포함)
eval.html         판별 정확도 평가 페이지
data/cases.json   개발용 판별 사례
```

## 기술 스택

HTML · CSS · JavaScript, Leaflet + OpenStreetMap(지도), Geolocation API(위치), Web Audio·Vibration API(가짜 전화), Claude(AI 분석, 아티팩트 버전)

## 개인정보와 악용 방지

- 제보에 사람·단체 이름을 적지 않도록 안내하고, 관리자 승인 후 게시
- 판별 결과는 참고용이며 특정 종교나 단체를 판단하지 않음
- 웹 데모의 예시 제보는 실제 사례가 아닌 예시 데이터이며, 지역 좌표는 대략적인 위치

## 향후 계획

- **공유 제보 DB**: Firebase 등으로 사용자 간 제보 실시간 공유 (현재 웹 데모는 이 기기에만 저장)
- **AI 서버 연동**: API 키를 숨기는 서버 함수를 거쳐 웹 데모에서도 AI 분석 제공
- **머신러닝 판별 모델**: 사용자 피드백과 제보로 라벨 데이터 500개 이상을 모으면, 문장 임베딩 기반 분류 모델을 학습해 `eval.html`에서 규칙 엔진과 정확도를 비교하고 더 나은 쪽을 채택하거나 결합
- **판별 피드백**: 결과마다 사용자가 실제 정답을 알려 주면 라벨 데이터로 저장해 정확도 측정과 학습에 활용
- **제보 신뢰도·지도 필터**: '나도 겪었어요' 공감 수와 최근성으로 마커 강도 조절, 기간·시간대·수법별 필터
- **판별 → 제보 연결**: 판별 결과에서 바로 제보 화면으로 이동
- **앱 전환(PWA·네이티브)**: 화면을 꺼도 위치 알림을 받을 수 있도록 백그라운드 위치 알림 지원
- **국내 지도 연동**: 카카오맵으로 건물·상호 단위의 정확한 위치 표시
